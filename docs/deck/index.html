Capstone

Build the thing that builds agents.

A multi-tenant agent platform. People describe an agent in plain English, your system builds and deploys it, they test it, and — once an admin approves — other companies can install it.

See the mockups Read the brief
The problem

Every team wants an agent. Every team writes it from scratch.

Today that means duplicated LangGraph code, hardcoded API keys in six repositories, and nothing anyone else can reuse or review. Nobody can answer "what agents do we have running, and what can they touch?"

Build the platform that fixes that.

Scope

Three tabs. That is the whole product.

MCP Registry
Register tool servers. Connect to them once with your own credentials.
Build
Chat to describe an agent. The platform picks tools, checks your access, builds it.
My Agents
Your agents as cards. Open one, test it in a playground, publish it.

Plus a Marketplace everyone can install from, and an Admin Review queue guarding the door to it.

The heart of it

The build is a graph that stops and asks you things

1 · Understand
Work out what the agent should do.
2 · Pick tools pause
Search the registry, show what it found, wait for you to choose.
3 · Check access pause
GitHub yes, Slack no — stop and ask for a token.
4 · Build and deploy
Write the configuration, create the agent, show the result as a card.

Four nodes, two pauses. Close the tab, restart the server, come back tomorrow — the build resumes exactly where it stopped. That is the single best lesson in this project.

Rule one

An agent is configuration, not code

When your platform "builds" an agent it must not generate and run Python. It writes a document. One runtime reads that document and assembles the agent.

What you get for free
Versioning. Rollback. No arbitrary code execution. And the ability to publish an agent into someone else's workspace at all.
What you have to work out
What that document needs to contain. That is the design problem, and it is yours.
Rule two

One person cannot see another person's things

My agents, my connections, my runs — mine. Nobody else in the platform sees them, and no other company's data reaches me.

Do not enforce this by remembering to add a filter to every query. One forgotten filter is a breach. Make it structurally impossible.

How this gets tested
We delete your application-level check and try again. Isolation must still hold.
Rule three

Credentials go in once and are never seen again

A token is encrypted on the way in. It never lands in an agent's configuration, a prompt, a log, or a saved conversation. When a tool needs it: fetch, use, drop.

Why this makes the marketplace possible
The configuration only says "this needs a Slack connection" — never which one. So it can be published without leaking anything.
How this gets tested
We search everything your system stored for the token we gave you. Finding it is a fail.
Rule four

Risky actions ask a human first

Any tool that writes or deletes pauses and waits. Enforced by the platform — not left to the agent's instructions, which are a suggestion, not a control.

In the playground this shows up as Approve and Reject buttons in the chat. Nothing is sent until someone clicks.

Rule five

Scores have to mean something

Every agent carries two numbers: how well it works, and how safely it is set up. You decide how to calculate them — but you must be able to point at exactly why a number is what it is. No asking a model to guess a score.

Then make them matter
An agent that scores badly cannot be published. The button is disabled and it says why. A score that blocks nothing is decoration.
Publishing

Nothing reaches the marketplace without a person

Hitting Publish starts a run that immediately stops and waits for an admin. That approval might sit for three days, across two deploys and a weekend.

Your system has to handle that. Answering picks the run up from exactly where it stopped: approve and it publishes, request changes and it goes back to the author with notes.

And publishing strips the company out
What travels is the design — what it does, what kinds of access it needs. We will hand you an agent with confidential material planted in it.
Rule six

Every agent is usable from outside the UI

Each agent gets a URL you can call. On its page there is a Download Postman Collection button — download it, hit Send, get a response.

One detail worth getting right
A token from another company that calls your agent's URL gets 404, not 403. A 403 confirms the agent exists.
Rule seven

At least one agent must be a real multi-agent system

Ship a demo agent that is more than a single tool-calling loop: a coordinator that delegates to two specialists, with a human approval step in the middle.

And it must be built through your own platform, not hand-written. That is the proof your platform can produce agents shaped like this, not just simple ones.

Deliverables

What to hand in

  • The running platform. docker compose up and it works. No paid accounts.
  • A demo recording walking the six steps, start to finish, without cuts.
  • A short design document — how you made each rule true, and what you would do differently with another month.
  • The multi-agent demo agent, built through your own platform.
Assessment

Nine checks. Each one passes or fails.

  • One user cannot reach another user's agents — with your filter removed
  • A credential we supply appears nowhere in anything you stored
  • An agent with an unguarded write tool cannot be published
  • Planted confidential material does not survive publication
  • Killing the server mid-build resumes correctly on restart
  • An approval left pending overnight still resumes the next day
  • The playground runs the multi-agent demo end to end, including its approval
  • The downloaded Postman collection gets a real response
  • Asking for another company's agent by ID does not reveal that it exists
Before you start

Two things that will save you a week

Go and look at LangSmith Fleet
It is a shipped product doing roughly what you are being asked to build. Read how it handles agent identity, approvals and schedules. Borrow shamelessly.
Do not plan on LangGraph Platform
It is not free, and self-hosting its server needs a paid licence key. Free tracing is available and worth turning on. Plan to run your own server.

Everything this project needs can be run for nothing. Free model tiers, or a model on your own machine, are fine.

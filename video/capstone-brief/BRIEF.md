# Agent Builder Capstone — problem statement video

**Message:** Your capstone is to build the platform that builds agents — here is the flow you
must deliver, the rules that make it real, and how you will be graded.

**Audience:** Students who have just finished the LangChain and LangGraph modules of the Data Sense
Agent Builder course. They know graphs, tools, interrupts and checkpointers. They have never built
a multi-tenant product.

**Destination:** Shared with the cohort alongside the GitHub repo and the mockup site. Watched once
at the start of the capstone, probably re-watched while building.

**Duration:** ~3 minutes (170–190s). Length is allowed to run long enough to cover grading.

**Format:** 1920×1080, 30fps, MP4. Narrated voiceover throughout.

## Story spine

Three acts, in this order. Do not reorder.

1. **The problem** (~35s) — every team builds its own agent from scratch. Duplicated code,
   hardcoded keys, nobody can answer "what agents are running and what can they touch?"
2. **What you build** (~110s) — the six-step flow, shown on the real mockups. This is the bulk.
   The build-chat step gets the most time: it must be *shown building*, not described.
3. **How you're graded** (~40s) — the rules, the nine checks, submit a GitHub repo, present live
   for 45 minutes.

## Must-haves

- Show the actual mockup screens: sign in, MCP registry, build chat, my agents, agent page with
  the graph, playground with the approval, admin review, marketplace.
- **The build chat must animate** — the user's request typing in, the platform proposing servers,
  the pause where it asks the user to pick, the pause where a credential is missing, then the
  finished agent card appearing. This is the centre of the video.
- Say plainly: submit a GitHub repository, and present live for 45 minutes.
- Name the nine checks as a group; do not read all nine out.
- End on the mockup URL so they know where to go.

## Tone

Direct and instructional, the way a good lead engineer briefs a team. Not a product promo. No
hype, no "revolutionize", no exclamation marks. Confident and calm. The student should finish it
knowing exactly what to build and slightly nervous about the grading.

## Visual direction

Inherit the mockup design system exactly — warm off-white paper (#faf9f7), near-black ink
(#191917), deep teal accent (#15544e), and the red requirement colour (#b3261e) used *only* for
rules and grading. Same typography scale. The video should look like it came from the same place
as the mockups.

Motion is functional, not decorative: things assemble, connect and pause. Avoid floating particles,
gradient meshes, and glow.
